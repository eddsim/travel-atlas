# Travel Atlas 旅行手册规范

> 参考实现：`public/trips/2026/09-24-phuket/index.html`。后续新国家 / 城市默认沿用相同的信息架构、视觉语言、交互和发布方式，只替换旅行数据与目的地资源。

## 1. 产品目标

Travel Atlas 不是普通攻略页，而是一份旅行当天会实际打开执行的手册。优先级：

1. 打开就知道下一步做什么：顶部“此刻关注” + 倒计时。
2. 快速定位：DAY1～DAYN + 待办 Sticky Tab。
3. 交通 / 酒店 / 景点可立即执行：导航 + 复制地点。
4. 弱网与离线可回看。
5. 公开页面不泄露订单、证件等敏感信息。
6. 页面结构稳定，下一次旅行只换内容，不重新设计。

## 2. 架构规范：单 Trip、单页面源

### 2.1 目录

```text
public/trips/<YYYY>/<MM-DD>-<destination>/
├── index.html       # 唯一页面源：内容 + CSS + JS
├── trip-map.png     # 总览地图，文件名可按目的地命名
└── assets/          # 可选其他图片资源
```

例如：

```text
public/trips/2026/09-24-phuket/
├── index.html
└── phuket-journey-map.png
```

### 2.2 禁止重新引入多层拼装

不要再使用：

```text
base.html → index.html 动态 fetch / 拼装 → Worker 再注入 HTML
```

原因：会产生多个事实来源、缓存复杂、排查困难，也容易出现某层更新但另一层仍旧的情况。

### 2.3 职责边界

`trip/index.html` 必须自行包含：

- 页面内容和视觉样式
- 倒计时 / 时区逻辑
- Sticky Tab
- 交通票卡
- 地图展示
- 地点复制
- 待办 localStorage
- 当次旅行独有数据

`src/worker.js` 只负责：

- 短路径 → 静态 `index.html` 路由
- workers.dev → 正式域名跳转
- HTTP 缓存头
- `/sw.js`
- 离线缓存 / 弱网回退

**Worker 不得硬编码某个目的地的 UI、航班卡、待办内容或 HTML 替换逻辑。**

## 3. 命名与 URL

目录：

```text
public/trips/<YYYY>/<MM-DD>-<destination>/
```

正式短路径：

```text
https://travel.606858.xyz/<YYYY>/<MM-DD>-<destination>
```

slug 使用英文小写 + 短横线；日期以出发月日开头，便于 GitHub 排序。

## 4. 页面固定信息架构

默认顺序不要随意打乱。

### 4.1 Hero

展示：目的地中英文名、日期、天数 / 晚数、同行人数（可选）、一句旅行定位。

### 4.2 此刻关注

必须包含：

- 下一事件标题
- 下一事件当地时间
- 实时倒计时：天 / 时 / 分 / 秒
- 事件时区按目的地绝对时间计算，不能依赖浏览者本地时区

如果下一事件是交通票务，显示交通卡：

- 航班：航司、航班号、出发 / 到达机场、航站楼、当地时间、时区、飞行时长
- 火车：车次、出发站、到达站、发到时间
- 大巴：运营商 / 班次、上下车点、发到时间
- 船票：船班、码头、开船 / 抵达时间

公开页不展示订单号、票号、证件号、座位号、二维码等敏感字段。

### 4.3 Sticky Tab

固定排列：

```text
DAY1 · 日期  DAY2 · 日期  ...  DAYN · 日期  待办
```

要求：

- 位于“此刻关注”下方
- sticky 吸顶
- 手机横向滑动，不换行
- 点击平滑跳到对应区域
- 滚动时自动高亮当前 Day / 待办
- `待办` 永远在最后一天之后
- Day 与待办区域设置 scroll-margin，避免标题被导航遮挡

### 4.4 行程总览地图

地图必须基于目的地真实地图轮廓 / 相对地理关系，再做手绘旅行杂志风格。

要求：

- 真实地理关系优先于装饰性
- 只标本次相关地点
- DAY1～DAYN 路线按天分色
- 天气条件 / 未确认路线使用虚线或弱化
- 酒店、机场 / 车站、核心景点有明确节点
- 图片作为正常静态资源引用，可直接在 GitHub 预览
- 不使用 Base64 txt / data URI 承载大图

推荐视觉：米白纸张感、低饱和水域 / 地形、深色手绘线、少量插画。

### 4.5 已确认预订

只放已出票 / 已确认内容：交通、酒店、接送、门票 / 活动。

尚未预订的项目必须标“待确认”，不能写成已确认。

### 4.6 DAY1～DAYN

每一天统一：Day 标签 + 日期星期 + 主题 + 时间轴 + 地点 / 活动 + 交通时间 + Plan B / 风险提示 + Google Maps 路线。

规划原则：固定交通先锚定；换酒店留缓冲；返程日优先机场 / 车站；营业时间、闭馆日和周末限定活动属于硬约束；天气敏感项目必须有备选。

### 4.6.1 景点 / 活动介绍层

时间轴不能只写“地点名 + 几点到”。对每个有旅行价值的景点、活动、商场、夜市、餐厅，至少补一层面向第一次看到这个名字的读者的解释。

每个重点 POI / 活动默认回答：

- **这是什么？** 1～2 句解释地点 / 活动性质，避免只堆专有名词。
- **为什么值得去？** 说明它在这趟旅行里的特色、价值或与其他地点的差异。
- **怎么玩 / 看什么？** 给出 1～3 个最值得关注的看点，不写百科式长文。
- **建议停留 / 节奏：** 对博物馆、夜市、体验项目等可给出大致停留感受；交通、退房、取行李等纯执行节点不强制添加。

推荐 UI：在时间轴事件正文下增加轻量“特色说明”块 + 2～3 个标签，例如“周日限定 / 街头小吃 / 手工艺”“历史街区 / 老建筑 / 咖啡小店”。信息密度要高，但不要把每个事件扩成一张大卡片。

介绍的目标是让没做过攻略的人只看本手册，也能理解“这个地方是什么、为什么排进来”。会变化的营业时间、价格、活动规则等仍需临近出发重新核实。

### 4.7 出发前准备 & 待办

必须可勾选并保存在 `localStorage`。

默认分组：

- 证件 / 入境
- 电子设备 / 网络
- 天气 / 目的地装备
- 出发前 24～48h
- 行程待办

交互要求：

- checkbox
- 完成后弱化 + 删除线
- `已完成 X / Y` + 进度条
- 刷新 / 重开仍保留
- “清空勾选”
- key 必须含 trip slug，例如：

```text
travel-atlas:2026-09-24-phuket:prep-checklist:v1
```

### 4.8 实用提示

按目的地补：入境 / 签证 / 入境卡、现金 / 支付、插座 / 电压、网络 / eSIM、天气、交通、安全 / 紧急电话、文化礼仪等。

会变化的政策 / 营业信息，在发布和临近出发时重新核实，不永久写死。

## 5. 地点交互

酒店、机场 / 车站 / 码头、景点、餐厅、商场、夜市、集合点默认同时提供：

1. Google Maps 导航 / 搜索
2. 复制地点 / 地址

有街道地址时复制完整地址；POI 更适合地图搜索时复制可识别英文 / 当地名称。复制成功使用轻量 toast。

### 5.1 Grab 一键打车

在 Grab 覆盖的目的地，行程时间轴中的可打车地点默认增加轻量 **「🚕 打车」** 按钮，放在地点链接 / 复制按钮右侧。

行为规范：

- 点击后使用 Grab 官方支持的 `grab://open?screenType=BOOKING` Deep Link 打开 Grab Transport。
- 尽量把当前 POI / 地址作为 drop-off 目的地带入；Grab 最终识别结果、上车点、车型与价格仍由 App 内确认。
- 不替用户自动下单，不跳过 Grab App 的最终确认。
- 桌面端或未安装 Grab 时 Deep Link 可能无法打开；Google Maps 与复制地点必须继续保留为兜底。
- 一条事件出现多个 POI 时，每个 POI 分别拥有自己的打车按钮，不把多个目的地混成一个按钮。

## 6. 视觉规范

关键词：`旅行杂志 / 手账 / 克制 / 温暖 / 轻量 / 移动端优先`。

- 中等偏大圆角
- 轻边框 + 很弱阴影
- 高信息密度，但保留明显留白
- Day 颜色在 Tab、Day 卡片、地图路线中保持同色语义
- 深浅模式下保证文字、checkbox、导航和复制按钮可见；地图图片不强制反色

避免企业后台风、霓虹渐变、过度玻璃拟态、过多卡片层级。

## 7. 图片资源

- 图片放在当前 trip 目录或 `assets/`
- 优先优化后的 WebP / PNG / JPEG
- 文件名英文小写短横线
- 必须有准确 alt
- 地图文字必须在手机宽度仍可读
- 压缩体积，但不要牺牲路线可辨识度
- 禁止 Base64 文本中转大图

## 8. 移动端 / 弱网 / 离线

- 375～430px 正常显示
- Sticky Tab 横滑
- 按钮触控区域足够
- 卡片无横向溢出
- 倒计时不换行错位
- 交通卡在窄屏可读

缓存：

- HTML 浏览器短缓存
- Cloudflare Edge 适度缓存
- Service Worker 保存最近成功打开的页面和关键静态资源
- 导航页面优先尝试新版本，弱网约 900ms 后快速回退缓存
- 第一次成功打开后，核心手册可离线回看；Google Maps 离线不可用属于正常限制

每次需要主动刷新离线结构时，递增 Service Worker cache version。

## 9. 隐私规范

公开页面严禁：护照 / 身份证号、个人手机号、订单号 / PNR / 票号、房间号、支付信息、二维码 / 条形码、可用于身份验证或改签的字段。

可以展示：航班号 / 车次、公共酒店电话、公开地址、出发到达时间、航站楼 / 车站、已确认状态。

订单截图写入页面前默认先过滤敏感字段。

## 10. 新旅行制作流程

1. 收集：目的地、日期、固定交通、酒店、想去地点、节奏 / 饮食 / 购物偏好。
2. 锁硬约束：航班 / 车次、入住退房、已出票门票、闭馆日、周末限定活动。
3. 排 DAY：先地理聚类，再算路程与缓冲，不用“景点列表”硬塞一天。
4. 做地图：真实地理关系 + 手绘视觉 + Day 分色。
5. 从普吉岛 `index.html` 复制结构到新 trip，替换数据、日期、时区、颜色、localStorage key 和地图资源。
6. 在 Worker 的 `TRIPS` 注册短路径；如需要离线预缓存，把新 trip 入口 / 关键地图加入 SW PRECACHE。
7. 更新 `public/index.html` 总入口。
8. 发布前按验收清单检查。

## 11. 发布验收清单

### 数据
- [ ] 日期 / 星期正确
- [ ] 时区正确
- [ ] 固定交通与酒店与订单一致
- [ ] 未确认项目没有伪装为已确认
- [ ] 营业 / 闭馆 / 周末限定已核实

### 页面
- [ ] 此刻关注倒计时正确
- [ ] 交通卡在对应事件出现
- [ ] DAY1～DAYN + 待办 Tab 完整
- [ ] Tab 跳转与滚动高亮正常
- [ ] 地图能直接加载，并在 GitHub 预览正常
- [ ] 每日路线 Google Maps 链接正常
- [ ] 重点景点 / 活动都有“这是什么 + 为什么值得去”的简短介绍
- [ ] 复制地点正常
- [ ] 待办勾选 / 进度 / localStorage / 清空正常

### 手机 / 弱网
- [ ] 390px 左右测试无溢出
- [ ] Sticky Tab 可横滑
- [ ] 关键图片已压缩
- [ ] Service Worker cache version 已按需更新
- [ ] 离线回看基本可用

### 隐私
- [ ] 无证件号
- [ ] 无订单号 / 票号 / PNR
- [ ] 无个人手机号
- [ ] 无二维码 / 条形码
- [ ] 无房间号 / 支付信息

## 12. 参考实现原则

普吉岛页面是当前“Golden Reference”。以后如果新旅行出现新的通用能力，先在对应 trip 验证，再同步回本规范；不要把目的地专属逻辑堆进 Worker。
